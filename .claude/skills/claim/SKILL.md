# Claim an issue

A claim is the first push of the branch `claude/<issue>`; whoever pushes first has the issue, because GitHub refuses the second push of the same name. The steps below are PROTOCOL.md's, in order. N stands for the issue's number throughout, and D for the default branch: the name `git symbolic-ref --short refs/remotes/origin/HEAD` prints after `origin/`, or main when it prints nothing. `<login>` stands for your own account's name: its label without the `account:` prefix, the name on the claim file's `- Account:` line (`main` only for the main account, whose label is account:main).

1. Fetch and read the board: `git fetch origin`, then `git fetch origin +refs/heads/board:refs/remotes/origin/board && git show origin/board:STATE.md`. The board is the file STATE.md on the branch `board`, rewritten by the board workflow; nobody edits it by hand. Take an issue the Queue section shows as unclaimed, labelled todo, with no open blocker in its way. An issue with a branch `claude/N` on origin or a file `docs/agents/claims/N.md` on the default branch belongs to another account.
2. Branch from the default branch: `git switch -c claude/N origin/D`.
3. Write the claim file `docs/agents/claims/N.md` from the template in docs/agents/claims/README.md: the account (`- Account: <login>`), the plan in a few sentences, the files you expect to touch, the issue's link.
4. Commit it alone, as the branch's first commit, and push: `git add docs/agents/claims/N.md`, `git commit -m "Claim #N"`, `git push -u origin claude/N`. Never with force.
5. If the push is refused because the branch exists, another account claimed it between your fetch and your push. Delete your local branch (`git switch D`, then `git branch -D claude/N`) and go back to step 1 with another issue.
6. Announce it on the issue: add the label claimed and your account's label account:<login>, and post the plan as a comment. With gh: `gh issue edit N --add-label claimed,account:<login>` and `gh issue comment N --body-file docs/agents/claims/N.md`. Where gh issue is refused, as in a cloud session, use the session's GitHub tools, or gh api: `gh api repos/OpenSpineConsortium/spine-program/issues/N/labels -f "labels[]=claimed" -f "labels[]=account:<login>"` and `gh api repos/OpenSpineConsortium/spine-program/issues/N/comments -F body=@docs/agents/claims/N.md`.
7. Open a draft pull request at once from `claude/N` to D, with "Closes #N" in its body, so the board lists the work from its first minute: `gh pr create --draft --base D --title "..." --body "Closes #N"`. Where gh pr is refused, use the GitHub tools, or `gh api repos/OpenSpineConsortium/spine-program/pulls -f title="..." -f head=claude/N -f base=D -F draft=true -f body="Closes #N"`. Push often. When the board comments "main moved", rebase on `origin/D` and push with `--force-with-lease`, the one forced push the protocol allows, and only on this branch.
8. Finishing is in PROTOCOL.md: the pull request deletes the claim file, says "Closes #N", passes this repository's own checks (none yet; check the acceptance lines of the issue by hand) and is marked ready; the issue gets the label in-review, and the merge closes it. With gh: `gh pr ready claude/N` and `gh issue edit N --add-label in-review`. Where gh pr is refused, mark the pull request ready with the GitHub tool update_pull_request (draft false), and add the label with the GitHub tools or `gh api repos/OpenSpineConsortium/spine-program/issues/N/labels -f "labels[]=in-review"`. Make sure you can mark it ready before you delete the claim file: with no such tool, say so, on the pull request and to the person, and stop there with the claim file still in place, because a draft pull request keeps its claim file and a ready one has none (PROTOCOL.md, "Rules that hold everywhere").
