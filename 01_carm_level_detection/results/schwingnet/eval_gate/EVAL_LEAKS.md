# EVAL_LEAKS: every quoted number against the held-out rule

Written 2026-09-24. The tables between `GENERATED` markers are filled by `leaks/build_eval_leaks.py` from
`chk9/chk9_report.json` and the re-scores in `leaks/`; the prose around them is written by hand. Nothing in the
manuscript files was edited: each finding names the sentence, figure or table it moves, and the manuscript workflow
owns the change.

**The rule** (Greg, 2026-09-23). An evaluation item is held out for a checkpoint only if its patient key is in
neither the train nor the val/selection set of that checkpoint, nor of any ancestor in its initialisation chain. A
render inherits its source CT subject. Public ImageNet/COCO weights are the only exempt ancestor, and only when
declared. Unknown is not clean.

**The verdicts used here.**

- CLEAN: CHK-9 HELD OUT.
- LEAKED: CHK-9 SEEN. An evaluation patient is in a train or val set on the chain; the overlap is named.
- UNRESOLVED: CHK-9 UNRESOLVED or NO EVAL KEYS. The chain has a link nobody can read, or the row names no pair the
  check can test; what is missing is named.
- N/A: no checkpoint (a count, a parameter, arithmetic or a published number).

Evidence the gate does not accept, stated so that it can be decided rather than assumed:

- the encoder file is dated 2026-09-15 08:11 and was registered 08:13;

change the rule, and that is Greg's call, not this sweep's.
