# Target layout on CephFS

Where every imaging source goes on `/rs/rs_grp_oschome/go2432` (`$RS`), how folders and files are named, what stays on
HOME, and the complete mapping from today's paths to the target. Written 2026-10-08. The mapping tables at the end
are generated by `plan/build_plan.py` from `plan/disk_map.csv` (family E's classification of the 2026-10-07
listing) and `sources.json`; rerun it with `--census` when the storage census lands, and these tables refresh.

## 1. The tree

```
$RS/data/
  <source_id>/                 one folder per upstream release or project release (the sources.yaml id)
    README.yaml                what this folder is: source ids, licence, access, restricted, roles, index adapter
    raw/                       as downloaded or as released, unchanged (DICOM, zips, the release's own tree)
    converted/                 format conversions of raw (NIfTI from DICOM, a release working copy)
    derived/<bank>/            renders, crop banks, pseudo-labels and exports built from THIS source only
    labels/                    label files that are not inside a release tree
    meta/                      manifests, crosswalks, fetch state (meta/reacquire/<id>/ is written by reacquire.py)
  multisource_banks/           banks built from several sources (allspine_*, films_drr, physics_drr, ...)
    README.yaml
    derived/<bank>/            each bank's sources are listed in plan/layout_map.csv and sources.json
    meta/                      the identity tables (patient_keys*.json, split_final.json, bank_splits.json)
  anomaly_harvest/<collection>/  the two-labeller screens (stays as it is)
  realxray/, realxray_work/    the real-frame layout (stays as it is; tools/patient_keys.py reads /realxray/<bank>/)
  _index/holding.sqlite        the index (db/build_index.py)
  _staging/<batch>/            transient: a batch's hard-link group (B02; the yolo* banks of B04) lands here before it
                               is renamed into place; the run removes it, and a rerun refuses leftovers it did not write
$RS/results/                   OPTIONAL (batch B13): nnU-Net results, ablations, bench, if Greg decides to move them
```

**Roles.** `raw` is what came from upstream; `converted` is a format change with no new information; `derived` adds
information or selects (renders, crops, pseudo-labels, exports); `labels` holds annotation files kept apart from a
release; `meta` holds tables about the data. The index (`db/`) records the role of every item.

## 2. Naming rules

1. **One folder per upstream release, named by its source id** in `sources.yaml` (`nhanes2_cdc_films`,
   `buu_lspine_3600`, `totalsegmentator_v300`). Two releases of one dataset are two folders (DeepFluoro has three:
   `deepfluoro_h5`, `deepfluoro_vendor`, and the HF re-host inside `polypose/`).
2. **Folders already on Ceph keep their names.** Tools and running chains name them (`tools/acquisition_fetch.py`
   writes `$RS/data/<collection>/`, `tools/cobra_fetch.py` defaults to `$RS/data/cobra2026/cases`, 536 code files
   name `$RS/data/...`, `plan/path_refs_summary.csv`). Where such a folder's name is not the source id, its
   README.yaml names the source:

   | existing Ceph folder | source id(s) |
   |---|---|
   | `data/idc` | `idc_tier1` and the 39 `idc_<collection>` sources (one pooled IDC v24 fetch) |
   | `data/ctpelvic1k_clinic` | `ctpelvic1k` (datasets 6-7) |
   | `data/geneva_hip_src` | `geneva_hip` |
   | `data/ljubljana` | `ljubljana_2d3d_gs` |
   | `data/thoracic_xr` | `aasce2019_boostnet` (the open mirror; TVGH probe results) |
   | `data/external/fluoro_video` | `fluoro_video_public_clips` |
   | `data/polypose` | `polypose_synthetic` and `deepfluoro_xvr_hf` (HF snapshot under `hf/`) |
   | `data/realxray`, `data/realxray_work` | `realxray_layout` (banks of carmlspine, cobra2026, deepfluoro_h5, geneva_hip, bournemouth_qf_cervical_tracks) |
   | `data/vindr`, `data/spineps`, `data/rare_class`, `data/ctsp0533_repair`, `data/d815_repair`, `data/ctsp_april`, `data/devcorpus_arc`, `data/outline_conv` | derived work folders of the sources their README.yaml lists |

   The acquisition collections keep their own sub-layout: `raw/` (role raw), `nifti/` (role converted), `fetch/`
   (role meta: `verified.jsonl`, `failed.jsonl`, `FETCH_STATUS.json`), and the screen in
   `anomaly_harvest/<collection>/` (role derived). Their README.yaml says so.
3. **Keep the original leaf name** of a moved folder under its role folder:
   `~/spine-detector/data/raw/nhanes_full` becomes `$RS/data/nhanes2_cdc_films/raw/nhanes_full`. This keeps the path
   fragments `tools/patient_keys.py` reads to name a corpus (lines 209-212: `/raw/nhanes_full/`, `/raw/buu_full/`,
   `/raw/csxa/`, `/ljubljana`, `/spinesac`, `/vindr`, `lateral236`, `/raw/lateral_236/`, and `/realxray/<bank>/`).
   Exceptions named in the mapping: the HOME copy of CTSpine1K lands at `$RS/data/ctspine1k/raw/home_copy` (a
   second copy beside the verified Ceph one; its README.yaml lists it under `index_skip`, so the index does not count
   the release twice), the PolyPose HOME working directory at `$RS/data/polypose/derived/polypose_home`, the
   render folders of `~/lstv_flag` at `$RS/data/multisource_banks/derived/lstv_flag/<folder>` (its `models/` and
   results stay on HOME), and two of the B14 items identified on 2026-10-08: `~/qc.tar.gz` lands at
   `$RS/data/ctspinopelvic1k_build_tree/derived/qc_2026-06-12.tar.gz` (a bare `qc.tar.gz` says nothing in a shared
   folder), and the scratch label copies `~/pitest` and `~/pdwtest` at
   `$RS/data/ctspinopelvic1k_build_tree/derived/scratch_2026-09-10/<name>`. `~/data/spondy_landmark`, a second
   download of Mendeley 5jdfdgp762, keeps its leaf beside the first copy (`raw/spondy_landmark` next to
   `raw/mendeley_716`) and is in that folder's `index_skip`.
4. **Ids stay as the release writes them.** CTSpinoPelvic1K ids are zero-padded (`0001`); the old CSVs were not, so
   `zfill(4)` before any join (CTSpinoPelvic1K-1/CLAUDE.md). NHANES sequence numbers are five digits, C-ArmLSpine
   cases `case<N>` (tools/patient_keys.py `_norm_person`, `canon_key`). Never rename a file inside a release.
5. **Never reorient on write.** Volumes are canonicalised to RAS in memory for analysis and written in the source's
   own orientation; `as_closest_canonical` + `nib.save` silently transposes a label away from its CT
   (CTSpinoPelvic1K-1/CLAUDE.md; memory note never-reorient-when-writing-labels). The migration copies bytes and
   writes no volume.
6. **Label schemes.** CTSpinoPelvic1K v11 is VerSe-native (L1 = 20 ... sacrum 26, 29 retired). Resolve names with
   `ostk.labels.labels_for(volume)`, never a fixed map (CTSpinoPelvic1K-1/CLAUDE.md).
7. **Derived banks are keyed to their source**: a bank built from one source lives in that source's `derived/`; a
   bank built from several lives in `multisource_banks/derived/` and its sources are listed in
   `plan/layout_map.csv` (column `disk_map_source_id`) and `sources.json` (`derived_of`).
8. **Restricted sources** (a named-person DUA or an EULA that forbids redistribution) get mode `0700`, owner only:
   `vindr_spinexr` (PhysioNet DUA), `buu_lspine_3600`, `buu_lspine_2000`, `buu_lspine_v1_smoke` (BUU EULA), and
   every bank that holds their pixels: each layout row whose disk-map sources name VinDr-SpineXR or BUU-LSPINE (the
   `allspine_*`, `extra_fov96_ctx`, `films_all2_fov96_ctx`, `films_drr`, `films_drr_buucorr`, `film_style_ds`,
   `mv_bands`, `pseudo_filtered`, `yolo_levels` banks, the VinDr and BUU banks of B10), the spine-detector
   `data/interim` and `data/yolo*`, and `~/dis_renders` (B14: five PNGs named by BUU films, so presumed to hold BUU
   pixels). One item is closed for another reason: `~/s1v11` (B14, the v11 build workspace) holds the Zenodo upload
   scripts and state, and stays owner-only until they are read for a token. `build_plan.py` flags them `restricted`; `migrate_batch.sbatch` copies them with
   `--chmod=go-rwx` and closes them again after the copy, so they are never group-readable on Ceph, not even before
   the cut-over; `cutover.sh` checks again. A mixed folder (`multisource_banks`, `spine_detector_corpus`) lists its
   closed sub-folders in README.yaml `restricted_subfolders`. The folder already on Ceph, `$RS/data/vindr`, is not
   closed by anything in this plan (its README says restricted); closing it is one command in a job,
   `sbatch -p reqp --qos=requeue --wrap 'chmod -R go-rwx /rs/rs_grp_oschome/go2432/data/vindr'`, for Greg to run
   once he has answered the open question. `/rs/rs_grp_oschome/go2432` is `drwxr-s---` with group `oschome` = go2432
   and <C&IT admin account, username withheld> (memory note grid-access-list-gate). Whether group read by a second account is allowed under those
   terms is not recorded; it is an open question for Greg, and closing the allspine banks owner-only affects any
   student who reads them.
9. **README.yaml** in every source folder (templates in `plan/readme_yaml/`, one per folder). Fields:

   ```yaml
   folder: "/rs/rs_grp_oschome/go2432/data/vindr_spinexr"
   source_ids: ["vindr_spinexr"]            # sources.yaml ids held here
   names: [...]
   families: ["D"]
   kind: ["upstream_release"]
   licence: [...]
   access: ["credentialed_dua"]
   restricted: true                          # 0700, never group-readable, never redistributed
   restricted_subfolders: []                 # in a mixed folder: the sub-folders that are owner-only
   permissions: "0700 (owner only): DUA or EULA"
   roles:                                    # sub-path -> role, for everything the migration puts here
     "raw/vindr": "raw"
     "derived/vindr_pseudo": "derived"
   existing_subfolders_kept: ""              # the acquisition sub-layout, when it applies
   index_adapter: "vindr_csv"                # the db/build_index.py adapter that reads this folder
   index_skip: []                            # sub-paths the index leaves out (a duplicate copy of the release)
   manifest: "data_platform/DATA_MANIFEST.md (cards: vindr_spinexr)"
   ```

   It is written in the subset `lib/mini_yaml.py` reads, so nothing on the grid needs PyYAML to read it.

## 4. Links that must survive

- **Container-path links.** `nnunet/raw/Dataset810/813/815/imagesTr/*` point at `/data/hf_export/ct/...`, a path
  that exists only inside the container. Never rewrite them; keep `HF_EXPORT_DIR` pointing at a directory with a
  `ct/` subfolder (`~/data/CTSpinoPelvic1K`, which becomes a symlink to
  `$RS/data/ctspinopelvic1k/converted/CTSpinoPelvic1K`; Singularity resolves a symlinked bind source).
- **Symlinks inside a bound tree.** When a job binds a HOME tree (for example `~/spinesurg-ct-nnunet`) into a
  container and a folder inside it has become a symlink to Ceph, the symlink dangles inside the container unless
  `/rs/rs_grp_oschome/go2432` is bound too. Bind that path, never `-B /rs` (memory note
  grid-local-singularity-is-broken). No script applies this rule by itself: `slurm/versefusion_totalseg.sh` binds
  only `~/VerSeFusion/data/unified`, whose links reach `raw/` and `canonical/` through the parent that moves in B06,
  so it now adds `/rs/rs_grp_oschome/go2432` to its binds when that path exists (2026-10-08); MIGRATION_PLAN.md
  section 6 lists the scripts to smoke-test after each cut-over.
- **Links written after the move.** `/rs` is a symlink into `/.rs/volumes/...` (memory note grid-ceph-volume-oschome).
  Code that builds a link with `Path.resolve()` or `realpath` (for example `tools/merge_versefusion_corpus.py`
  `link_or_copy`) records the `/.rs/volumes/...` path once its input sits on Ceph, and a container that binds
  `/rs/rs_grp_oschome/go2432` cannot see that path. Build such links from the `/rs/rs_grp_oschome/...` spelling.
- **Symlinks already in the trees**: `~/bench/ct_by_case` (802 links), `~/VerSeFusion/data/unified` (88 MB of links,
  which is why `~/VerSeFusion/data` moves as one unit), `~/spine-detector/data/raw/buu_2000` ->
  `~/XRSpinoPelvic1K/data/BUU-LSPINE`, `$RS/data/validation_ts/raw/*` -> `$HOME/data/TotalSegmentator/<s>/ct.nii.gz`,
  `~/user/diffdrr_data` -> `~/deepfluoro/data`. Each still resolves through the symlink left at the old path.
  Whether the links are absolute or relative is not recorded; `plan/preflight.sbatch` counts, per item, absolute and
  dangling links and relative links that leave the item. `plan/verify_transfer.py` fails an item in which a link
  that resolved at the source does not resolve at the copy (a relative link such as `../verse_drr/x` inside a bank
  points at a sibling that is not there after the move); such an item stays VERIFY_FAILED until its links are
  rewritten or the item it points at moves beside it. Links that dangled already (the container paths) do not fail.
- **Hard links.** The 802 CTs in `~/data/CTSpinoPelvic1K/ct` were hard-linked from
  `~/CTSpinoPelvic1K/data/hf_export_osc/ct` (`CTSpinoPelvic1K-1/slurm/archive_build_inputs.sh` line 73); the build
  tree links files between its own folders too (`slurm/ship_v5.sh` `cp -al`; `scripts/build_v6.py`,
  `build_v3_totalseg.py`, `intensity_refine.py`, `pseudolabel.py` `os.link`). Hard links cannot span Panasas and
  CephFS or two rsync calls, so every B02 item is in one hard-link group: one `rsync -aH` call into
  `_staging/B02`, then renamed into place. The spine-detector `yolo*` banks are a second group (B04).
  `verify_transfer.py` fails a file whose hard-link count differs between source and copy, so a partner left
  behind shows instead of silently becoming a second copy; the 192.8 GB the two B02 trees share are counted once in
  the batch total.
