# CTSpinoPelvic1K-Syn

Offline generator (and released dataset) of **synthetic LSTV cases**, one per
Castellvi class, for the CTSpinoPelvic1K spine+pelvis CT segmentation project.

Sibling to **CTSpinoPelvic1K**: the main repo builds the *real* dataset; this
repo manufactures *anatomically-grounded synthetic* lumbosacral transitional
vertebrae (LSTV) to supplement the handful of real LSTV cases (some subtypes
have n=2). It produces nnU-Net-ready `imagesTr/labelsTr` NIfTIs + a origin
manifest, and the generated set is released on HuggingFace as
`CTSpinoPelvic1K-Syn`.

## Why this exists

The hard part of LSTV is not the vertebral *body* — it's the **transverse
process (TP) ↔ sacral ala relationship**, which is exactly what Castellvi
grades and what the prior crude augmentations (copy-paste a whole vertebra,
registration warp) do **not** reproduce. This repo generates the *defining*
morphology per grade, with a voxel-exact label by construction.

## Castellvi classes generated

| Code | Type | Sides | Defining feature (per affected side) |
|------|------|-------|--------------------------------------|
| Ia   | I    | unilateral | dysplastic/enlarged TP (≥19 mm craniocaudal) |
| Ib   | I    | bilateral  | dysplastic TP both sides |
| IIa  | II   | unilateral | pseudoarthrosis (TP–ala false joint) |
| IIb  | II   | bilateral  | pseudoarthrosis both sides |
| IIIa | III  | unilateral | bony fusion (TP–ala bridge) |
| IIIb | III  | bilateral  | fusion both sides |
| IV   | IV   | mixed      | pseudoarthrosis one side + fusion the other |

(Sacralization vs lumbarization is the *count* axis, handled separately by the
ported warp/copy-paste generators; Castellvi is the *junction-morphology* axis.)

## Pipeline (offline producer contract)

```
in:  real labeled normal/donor cases (CTSpinoPelvic1K HF export) + (class, seed)
out: synthetic CT+label NIfTIs (nnU-Net raw layout) + synth_manifest.json
```

1. **procedural** — deform a normal spine to create the Castellvi feature
   (grow the TP, carve a pseudoarthrosis with sclerotic margins, or bridge bone
   to the ala), per side. Label generated by construction → voxel-exact GT.
2. **blend** — Poisson / gradient-domain seam blend (label-safe: edits
   intensities only). This is the cheap classical step that does the real work
   (Martinson et al. CVPRW 2021 found GAN refinement looked nicer but did *not*
   help training); keep it primary.
3. **refine** *(optional, ablatable)* — diffusion texture refiner over the
   modified region only, mask-conditioned so the label stays exact. Treated as
   an experiment arm, not a load-bearing step.
4. **manifest** — every case tagged `SYNTH_…` with full origin.

## Split hygiene — non-negotiable

Synthetic cases are **training-only**. Every synthetic caseID is prefixed
`SYNTH_`, and the downstream convert/splits step must keep `SYNTH_*` out of
`val`/`test`. A synthetic case leaking into validation/test silently inflates
metrics and invalidates the result. `ctspino_syn.manifest.audit_splits_no_synth_leak()`
checks a `splits_final.json` for violations. If synthetics are used for
*calibration*, emit them as a **separate** synthetic-val split — never mixed
with the real test set.
