### 2.2 Beethoven: how students reach the grid (pointer; not re-documented)

Beethoven is the lab's Chrome extension plus the `hpcworker` framework; it starts a Claude Code worker as a Slurm job in
the student's own grid account and opens it in claude.ai through Claude Code Remote Control (`bth:CLAUDE.md`;
`bth:docs/guides/USE.md`). Guides for 14.0.0 (2026-10-03): `bth:docs/guides/INSTALL.md`, `USE.md`, `ACCOUNTS.md` (header
says 12.0.0), `LAB_LEAD.md` (header says 12.0.0; §11-12 cover 14.0.0) and the one-page
`bth:release/14.0.0/guides/STUDENT_QUICKSTART.md` (title still says 12.0.0; no copy under `docs/guides/`).

A student needs a WSU AccessID with a grid account, Claude Pro or Max (paid by the student), Chrome signed in to the
Google account the private-listing invitation went to, Google Authenticator, GlobalProtect once.

**The approved list.** Approval is given in the access service (`admin.mjs approve <id>` or `grant <id> extension`;
`admin.mjs roster` prints approved AccessIDs). On the grid "approved" means a named ACL entry `user:<AccessID>:rwx` on
`/rs/rs_grp_oschome` (`drwxrws--T`, `other::---`, sticky). Group `oschome` is NOT the list (C&IT owns it; it holds
go2432 and ab5188). Below the gate, `shared/` and `shared/beethoven` are other-readable; `shared/access` and `go2432/`
stay closed. `bth:tools/grid_access.sh` (from WSL, or the Windows scheduled task "Beethoven grid access") keeps the ACL list
equal to the roster about every fifteen minutes while Greg's PC is on. By hand: `setfacl -m u:<id>:rwx /rs/rs_grp_oschome/`,
remove with `setfacl -x u:<id>`. A student not yet on the list sees exit 126 "Permission denied" on
`.../shared/beethoven/hpcworker/current/bin/hpcworker` (`bth:docs/guides/LAB_LEAD.md` §8-9; `context/grid-access-list-gate.md`).

**When the panel hangs**, read `sacct -u <id> -S <today>`, the run's `status.json`, the gate's caps file and `last -F <id>`
before touching code: "the grid tells the truth and the panel may not". Known open items (memory note
`beethoven-2026-10-02-field-failures`, copied to `GREG_ONLY/context_beethoven/`): VPN-route Claude sign-in sittings die about 5 minutes after
the last keystroke (Open OnDemand idle sweep; a terminal `hpcworker claude login` works); `reqp --qos=requeue` preempts
workers (switching the Wayne profile to `secp/secondary` is Greg's call, `bth:framework/profiles/wayne.json` lines 8-11).

## 3. How a job is written and submitted

**Minimal template**: `ssn:slurm/paired_sets_properties.sh` (`#SBATCH --partition=reqp --qos=requeue --no-requeue`, 2 CPUs,
8 GB, 30 min, absolute `--output=/wsu/home/go/go24/go2432/model_night/logs/<name>_%j.out`, `set -u`,
`cd ~/spinesurg-ct-nnunet`, `export PYTHONNOUSERSITE=1 TMPDIR=$H/tmp OMP_NUM_THREADS=2`, the env's python by full path, a
`*_DONE` marker) (`context/no-jobs-on-login-node.md`).

**The lab skeleton**: `students:RECIPE.md` §5 (a header comment saying what the job produces and how to resume it;
`set -uo pipefail`; required variables `${LIST:?}`; a `/dev/shm` work directory with a trap; step 0 refuses on missing or
empty inputs or a changed `PREREG.md.sha256`; exit codes 0 done / 1 refused / 3 nothing to do / 4 resubmit). The 14 grid
rules with the incident behind each are in the same section.

Conventions, with counts over `ssn:slurm/*.sh` (583 scripts, 2026-10-08):

| convention | count | why |
|---|---|---|
| `#SBATCH --output` is resolved against the **submit** directory | 60 scripts use a relative `logs/`; 270 the absolute `~/model_night/logs/` | submit relative-output scripts with `sbatch -D <dir>`; the target folder must exist |
| `afterany`, not `afterok` | 55 use afterany; 32 still contain afterok | afterok strands chains |
| `/dev/shm` for IPC and scratch | 58 | `/tmp` is swept |
| `TMPDIR=$HOME/tmp` | 227 | the older convention; it spends HOME quota (94 % full on 2026-10-07): prefer `/dev/shm` for small scratch, Ceph `tmp/` for large |
| `sbatch --parsable`, strip `${ID%%;*}`, write the id with a timestamp to the project's `JOBS.txt` | — | ids that lived only in a terminal were lost (`students:RECIPE.md` rule 13) |
| a dependent job whose input is not ready resubmits itself `afterany` (or `--begin=now+30minutes`) and exits 0 | — | never wait on a node (rule 9) |
| arrays walk one list through atomic claims (`mkdir` / `O_EXCL`), stale takeover, heartbeat, GPU self-test, failure-streak stop | — | Blackwell nodes under a CUDA 12.4 build (rule 8) |
| one LaTeX compile at a time (`flock`) | — | interleaved `main.aux` left a stale PDF (rule 11) |
| a pre-registered decision gate (`DECISION.json`) between a timing run and a production array | — | cost control on the 21,622-CT census (rule 14) |
| scripts are files in the repository; never heredocs over ssh, `sbatch --wrap`, or `python -c` with backslashes | — | backslashes collapse in heredocs (`context/bash-heredoc-backslashes.md`) |
| `PYTHONNOUSERSITE=1` in every job; CPU tools with `python -P` | — | a user-site package or a stray `struct.py` shadowed imports (`ssn:env/README.md`) |
| a new pipeline stage is added to `tools/pipeline_state.py` | — | a hard-coded `rung_0.npz` silently retired the best model for months (`ssn:CLAUDE.md`; `context/fluorocap-pipeline-resume.md`) |

After a run: `~/mambaforge/envs/spineps/bin/python ~/spinesurg-ct-nnunet/tools/pipeline_state.py` computes done / running /
ready / blocked / failed from disk and queue and writes `~/model_night/PIPELINE_STATE.md`. **Run it in a job**: `ssn:CLAUDE.md`
says to run it over ssh on the login node, which predates the warrior ban on python.

## 7. OpenSpineToolkit (ostk)

- A tested Python package of geometry primitives and measurements (PI / SS / PT, lumbar lordosis, PI-LL + SRS-Schwab
  modifiers, coronal Cobb, per-level morphometry, six-point vertebral morphometry) plus `projects/<name>/` student
  miniprojects. Modules `labels, io, geometry, masks, spine, metrics, metrics2d, cobb, morphometry, vertebral_body, genant,
  drr, project2d, surgery, record, parallel, cli`. CLI `python -m ostk {pi,ll,cobb,all,morph} --labels <dir> --out <file>
  --workers 8`; tests `python -m pytest` (94 test functions). All geometry in world millimetres via the affine; the
  sagittal plane from the femoral-head axis; bad cases return `value=None` + `qc_flags`, never an exception
  (`ostk:CLAUDE.md`). `ostk:SPEC.md` is the technical contract (it, `README.md` and `CLAUDE.md` still describe the legacy v3
  scheme, `lid()`, "27 tests" and a blanket "SVA/TPA out of scope" claim Greg removed: stale).
- **The two label schemes trap.** Release v10 / v11 (VerSe-native): C1-C7 = 1-7, T1-T12 = 8-19, L1-L6 = 20-25, sacrum 26,
  coccyx 27, T13 28, (S1 29 in v10 only), hips 30 / 31, femurs 32 / 33, ribs 34-59, lumbar ribs 60 / 61, hardware 62-68.
  Legacy ostk / PACS demo: L1 = 1, S1 = 7, sacrum 8, hips 9 / 10, femurs 11 / 12. Mixing them does not raise ("femur_left"
  comes back T4). Call `ostk.labels.labels_for(volume)` (detects by pelvis voxel mass, raises `SchemeError` when ambiguous);
  `lid(name)` without a volume is "the thing to avoid in new code" (`ostk:ostk/labels.py`; `context/label-scheme-v4-vs-ostk.md`;
  `context/scheme-bone-hardware-only.md`).
- **Id 29 is retired in v11**; code that gates on 29 must go with it; and ostk's own `LABELS_V10` still maps "S1": 29, so
  on v11 volumes the S1 end-plate falls back to the whole sacrum without a flag (`RESULTS_CATALOG.md` G.3).
- **Open defect**: commit 1b7005c (2026-09-10) ring closing inflates posterior body height / end-plate depth by 10-17 mm on
  about one vertebra in seven with no gate; `canal_mask min_vox=20` admits 3 mm canals; no fix through cb43197
  (`context/ostk-canal-closing-regression.md`; `RESULTS_CATALOG.md` G.2).
- Volumes are stored (P, I, R): canonicalise to analyse, never to write; read directions with `nib.aff2axcodes`
  (`context/ct-volumes-are-pir-not-ras.md`; `context/never-reorient-when-writing-labels.md`).
- The PACS demo (`openspineconsortium.github.io/pacs/`) is driven by `pacs/data/<case>/metrics.json` from
  `ostk:tools/export_demo_case.py` (the exporter imports `lid`; case 0003 is a v3-scheme case) (`context/pacs-demo-and-ostk-params.md`;
  `context/engine-swap-architecture.md`).
